The conditions for using this result are explicit:

1. First obtain an actual unbounded admission theorem for the exact native query or a sound overapproximation. A timeout, bounded pass, or sample trace cannot be transferred as a proof.
2. Retain the same initial reset, immutable zero-fault instruction ROM, and external memory/service domain. Replay the decoder and cumulative RF certificates and freeze all source, model, and log dependencies with Python assertions enabled.
3. Start the eventual physical RS candidate from the exact cumulative RF baseline. Independently close the RS rewrite using the admission theorem and the relevant row/reset and consumer-observation arguments. An admission bound by itself does not prove an arbitrary hardware edit equivalent.
4. Measure the RS increment against this same cumulative baseline and mapping flow. Do not count existing program/RF savings again as timing-induced savings. Keep all proof-only predicates, reset simplifications not separately accepted as hardware, and payload abstractions out of the physical candidate.

Two integration traps matter only if the RF candidate is later used to accelerate queries. Its 32 new decode-output wire IDs, `230483` through `230514`, collide with outputs in the existing decoder-only word-predicate encoding. Regenerate the seven predicates after loading the RF candidate; copying the old 119 cells would create multiple drivers. The 57 source-native word-projection cells themselves remain unchanged.

Also replay RF equivalence before applying the inactive reset rewrite. That rewrite changes ten full cells from the RF certificate's 381-cell destination-field projection, so claiming that projection remains literally unchanged afterward would be incorrect. The already-proved equivalence and pointwise reset facts still compose, as the exact commutation check demonstrates. Existing importers correctly reject an unexpected candidate hash; integration needs an explicit cumulative-certificate bridge, not broadly weakened identity checks. The ROM producer and port boundary remain identical, but the importer binds the complete native descriptor hash, so rebind through exact extracted-producer/port equality and proof-model replay while separately recording the new native candidate hash.
